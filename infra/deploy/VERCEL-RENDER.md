# Fast free hosting: Vercel + Render + Atlas

For the introduction class only. No VM, no domain, no SSH, no credit card.
Budget ~40 minutes. Everything below is free tier.

```
student browser
      |
      v
breachkeep.vercel.app          <- Vercel serves the React app
      |  /api/* is rewritten (proxied), not redirected
      v
breachkeep-api.onrender.com    <- Render runs apps/api
      |
      v
MongoDB Atlas M0
```

**Why the rewrite matters.** The browser only ever talks to `vercel.app`, so the
login cookie is a first-party cookie. If the app called Render directly the
cookie would be third-party, and Safari and Chrome incognito block those by
default — roughly a third of your class would be unable to log in with no
visible error. Do not skip the rewrite.

---

## Before you start

Have these three browser tabs open and be signed in with GitHub:

- https://cloud.mongodb.com
- https://dashboard.render.com
- https://vercel.com

Your code must be pushed to GitHub. From the repo folder:

```powershell
git add -A
git commit -m "Deploy config for Vercel + Render"
git push
```

---

## Step 1 — MongoDB Atlas (8 min)

1. cloud.mongodb.com → sign in with Google → **Create a cluster**.
2. Choose **M0 FREE**. Any region (Mumbai is closest). → **Create Deployment**.
3. A **username and password** box appears. Enter a username, click
   **Autogenerate Secure Password**, and **copy the password now** — it is not
   shown again. → **Create Database User**.
4. Left sidebar → **Network Access** → **Add IP Address** →
   **ALLOW ACCESS FROM ANYWHERE** (`0.0.0.0/0`) → **Confirm**.
   Render's free tier has no fixed outbound IP, so this is required.
5. Left sidebar → **Clusters** → **Connect** → **Drivers** → copy the string:

   ```
   mongodb+srv://USER:<db_password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```

6. Replace `<db_password>` with the password from step 3, and insert the
   database name `breachkeep` before the `?`:

   ```
   mongodb+srv://USER:THEPASSWORD@cluster0.xxxxx.mongodb.net/breachkeep?retryWrites=true&w=majority
   ```

   Keep this in Notepad. This is `MONGODB_URI`.

> If the password contains `@ : / ? # [ ] %`, percent-encode it (`@` → `%40`).
> Autogenerated passwords are safe; a hand-typed one may not be.

## Step 2 — Gather your secrets (5 min)

Open PowerShell in the repo folder.

**Admin password hash:**

```powershell
cd apps\api
npm install
npm run hash-admin "PickAStrongAdminPassword"
```

Copy the `$2a$...` string it prints. That is `ADMIN_PASSWORD_HASH`.
Remember the plaintext — it is what you type to open the Warden panel.

**Three random secrets** — run this three times and keep each result:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

**Gmail app password** (for the student verification emails):
myaccount.google.com → Security → 2-Step Verification must be ON →
**App passwords** → name it `breachkeep` → copy the 16-character code.
That is `EMAIL_PASS`; `EMAIL_USER` is the full Gmail address.

**Google OAuth client id:** console.cloud.google.com → create/select a project →
**APIs & Services → Credentials → Create Credentials → OAuth client ID** →
Application type **Web application**. Leave the origins empty for now — you fill
them in at Step 5, once you know your Vercel URL. Copy the **Client ID**
(ends in `.apps.googleusercontent.com`).

## Step 3 — Render: the API (10 min)

1. dashboard.render.com → **New** → **Web Service** → connect your GitHub repo.
2. Fill in:

   | Field | Value |
   |---|---|
   | Name | `breachkeep-api` |
   | Language | Node |
   | Branch | `testing` (or whichever you pushed) |
   | **Root Directory** | `apps/api` |
   | Build Command | `npm ci` |
   | Start Command | `node src/server.js` |
   | Instance Type | **Free** |

3. **Environment Variables** — click *Add Environment Variable* for each.
   The API refuses to boot if any of these is missing, so add all of them:

   | Key | Value |
   |---|---|
   | `NODE_ENV` | `production` |
   | `MONGODB_URI` | the string from Step 1 |
   | `JWT_SECRET` | random secret #1 |
   | `FLAG_HMAC_SECRET` | random secret #2 |
   | `PROVISIONER_SHARED_SECRET` | random secret #3 (unused today, still required) |
   | `COMMON_ACCESS_CODE` | what you read out to the class, e.g. `BREACH-2026` |
   | `ADMIN_LANDING_CODE` | a second code only you know |
   | `ADMIN_SECRET_PATH` | `/keep-warden-7f3a9c` (change the suffix) |
   | `ADMIN_PASSWORD_HASH` | the `$2a$...` string |
   | `EMAIL_USER` | your Gmail address |
   | `EMAIL_PASS` | the 16-char app password |
   | `GOOGLE_CLIENT_ID` | the `.apps.googleusercontent.com` id |
   | `TRUST_PROXY_HOPS` | `2` |
   | `AUTH_RATE_MAX` | `400` |
   | `BCRYPT_COST` | `10` |

   **Do not set `COOKIE_DOMAIN`** and **do not set `PORT`** — Render provides
   the port, and a wrong cookie domain silently breaks every login.

4. **Deploy Web Service.** Watch the log. Success looks like:

   ```
   [db] connected
   [api] listening on :10000
   ```

   If it says `Missing required env vars: ...`, add the ones it names and
   redeploy. If it hangs on the database, re-check Network Access in Atlas.

5. Copy your service URL from the top of the page:
   `https://breachkeep-api.onrender.com`. Open
   `https://breachkeep-api.onrender.com/api/health` in a tab — you want
   `{"ok":true,"service":"breachkeep-api"}`.

## Step 4 — Point the frontend at it (2 min)

Edit `apps/web/vercel.json` and replace `REPLACE-ME` with your real Render
hostname:

```json
"destination": "https://breachkeep-api.onrender.com/api/:path*"
```

Then:

```powershell
git add -A
git commit -m "Point web rewrite at Render"
git push
```

---

## Step 5 — Vercel: the frontend (8 min)

1. vercel.com → **Add New… → Project** → import the same GitHub repo.
2. Fill in:

   | Field | Value |
   |---|---|
   | Framework Preset | **Vite** |
   | **Root Directory** | `apps/web` (click *Edit* and pick the folder) |
   | Build Command | `npm run build` |
   | **Output Directory** | `dist/app` |
   | Install Command | leave default |

3. **Environment Variables** (expand the section before deploying — these are
   compiled into the JavaScript at build time, so adding them later means
   redeploying):

   | Key | Value |
   |---|---|
   | `VITE_API_BASE` | `/api` |
   | `VITE_GOOGLE_CLIENT_ID` | the same Google client id |
   | `VITE_ADMIN_PATH` | **exactly** the same string as `ADMIN_SECRET_PATH` |

4. **Deploy.** You get `https://breachkeep-xxxx.vercel.app`.

5. **Now finish Google.** console.cloud.google.com → Credentials → your OAuth
   client → **Authorised JavaScript origins** → **Add URI** →
   `https://breachkeep-xxxx.vercel.app` (no trailing slash) → **Save**.
   Changes can take a minute or two to apply.

> Use the **production** URL, not a preview URL. Vercel gives every push its own
> preview URL and Google will reject origins you have not listed.

## Step 6 — Test it before class (5 min)

Open the Vercel URL in a **private window**.

- [ ] Access-code page appears.
- [ ] `COMMON_ACCESS_CODE` is accepted → registration form.
- [ ] Register with a real email → the 6-digit code arrives → you land in the app.
- [ ] Google sign-in: popup opens, returns, logs you in.
- [ ] Intro module loads, all three rooms complete, sorting assigns a house.
- [ ] Warden panel opens at `https://<your-vercel-url>/keep-warden-7f3a9c`.
- [ ] **Site → Close the site now**, check in another private window that the
      maintenance page shows, then **Reopen the Keep**.

**Wake the API ~5 minutes before class.** Render's free tier sleeps after 15
minutes idle and takes ~50 seconds to wake. Just load
`https://breachkeep-api.onrender.com/api/health` and wait for the JSON.

## If something breaks

| Symptom | Cause |
|---|---|
| Access code accepted, then bounced back to the code page | The `/api` rewrite in `vercel.json` still says `REPLACE-ME`, or you redeployed without it. Cookie never got set. |
| Google button missing | `VITE_GOOGLE_CLIENT_ID` was empty at build time. Add it in Vercel → **Redeploy**. |
| Google popup opens and instantly closes | The Vercel origin is not in Authorised JavaScript origins. |
| Admin password accepted but the box reappears | `VITE_ADMIN_PATH` ≠ `ADMIN_SECRET_PATH`. |
| First student waits ~50 s, everyone after is fine | Render cold start. Expected. |
| "Too many attempts, try again later" | `AUTH_RATE_MAX` too low or `TRUST_PROXY_HOPS` not `2`. |
| Verification email never arrives | Gmail **app password**, not the account password, and 2FA must be on. |
| API log: `Missing required env vars` | Add the named variables on Render and redeploy. |

## What you are giving up versus the VM setup

Worth knowing, not worth fixing today:

1. **The nginx gate is gone.** On the VM, the app bundle is never sent to a
   browser without a gate cookie. On Vercel the whole app bundle is public, so a
   curious student can read the route names in the JavaScript. Every API route
   still checks the cookie server-side, so they cannot *do* anything — but the
   structure is no longer hidden.
2. **No dungeons.** Challenge containers need the Docker socket. Neither Vercel
   nor Render will give you that. Moving to a VM is unavoidable before Class 2.
3. **Render sleeps** after 15 minutes idle on the free tier.
4. **Atlas M0** is 512 MB and shared CPU. Fine for a cohort of 150 doing the
   intro module.
